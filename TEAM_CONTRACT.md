#1.Communication Plan

To ensure smooth collaboration, the team will maintain consistent communication and transparency throughout the project.

| Communication Type | Platform | Frequency | Responsible |-------------------- |----------- |------------ -------------- | Daily updates | WhatsApp Group | Every day | All members | | Weekly meetings | Zoom / Google Meet | Every Friday at 4:00 PM | Team Leader (Kithworths) | Task tracking | Trello Board | Updated after each task | All members | Urgent communication | Direct phone call | As needed | Team Leader

Guidelines:

Each member must provide a progress update before weekly meetings.
Missed meetings must be communicated 24 hours in advance.
Trello cards must reflect accurate progress (To Do / In Progress / Done).
#2. Git Workflow

The team will use GitHub for version control and collaboration under the lgu-it organization.

Branching Strategy

main → Stable production code only.
dev → Development and integration branch.
feature/* → Used by individual members for new modules or fixes.
(e.g., feature/parser-module, feature/api-endpoints)
Commit Message Format Follow this pattern for consistency:

feat: add parser for fixed-width .dat files
fix: correct year parsing logic
docs: update README with installation steps
Pull Requests (PRs)

Every feature or fix must go through a Pull Request before merging to dev or main.
At least one peer review is required before merging.
No direct commits to main are allowed.
#3. Code Review Standards

The team will follow these standards to ensure quality, maintainability, and professionalism.

Review Aspect Expectation
-------------------------|----------------------------------------------------------------------- | Readability | Code must use clear naming conventions, indentation, and comments | Functionality | Code should perform the intended function and pass tests | Modularity | Logic must be separated into logical modules (Parser, API Server, etc.) | Documentation | Functions and classes must include brief descriptions | Testing | Each new feature should include or update corresponding test cases

#Process:

Each Pull Request must be reviewed by at least one other member.
Reviewers will leave constructive feedback in GitHub comments.
Changes must be approved before merging.
All team members share equal responsibility for maintaining high-quality code.
#4. Conflict Resolution Process

Conflicts may arise regarding to code decisions, task assignments, or schedules. The team will follow this fair, structured resolution process:

Private Discussion :Members involved will discuss the issue respectfully and attempt to find common ground.
Team Mediation :If unresolved, the issue will be discussed in the next scheduled team meeting led by Kithworths.
Voting System :All four members will vote on the best resolution. Majority decision wins.
Escalation :If the matter remains unresolved, it will be escalated to the course lecturer for guidance and mediation.
Ground Rules:

Respect all opinions and maintain professionalism.
Focus on solving the issue, not assigning blame.
Document all major decisions on Trello for transparency.
#5. Collaboration & Accountability

All tasks will be created and tracked on Trello, categorized as To Do, In Progress, or Done.
Each member must: - Update progress on Trello at least twice a week. - Push commits regularly with meaningful messages. - Participate in at least one code review per week. - Deadlines will be reviewed every Friday during the team meeting.
#6. Agreement

By signing this contract, each member agrees to:

Contribute equally and meet assigned deadlines.
Maintain open communication and professionalism.
Follow the Git workflow and code review standards.
Respect the conflict resolution process.
